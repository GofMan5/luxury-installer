# Luxury Installer working contract

- Windows peer Authenticode проверяет объект реально запущенного image: pathname открывается без write/delete sharing, затем связывается с process section через `ProcessImageFileMapping`. Path-only WinTrust/recheck запрещён.
- System Setup получает initial/retry maintenance state только через privileged read-only `prepare_system_install`; нельзя фабриковать `Install`. Setup-действие атомарно захватывает startup gate до проверки close-state; закрытие ждёт переход `starting -> active`, отменяет активную установку/удаление и ждёт terminal rollback/cleanup в одном bounded budget. Повторный native close/Alt+F4 остаётся заблокирован до отдельного `close_ready`, который Rust выставляет только после shutdown; cancel-request использует остаток того же budget.
- Windows release подписывается в две фазы: одинаково подписанные inner Tauri/backend -> `cargo windows-release-setup` -> внешняя подпись outer NSIS -> `cargo verify-windows-release`. Ни один Rust command не принимает signing credentials.
- Production CSP не содержит `unsafe-inline`; динамический UI использует native elements/static CSS. Dev-only Vite CSP остаётся отдельным.

- Делай изменения маленькими вертикальными срезами: `spec -> use case -> adapter -> CLI/GUI`.
- `luxury-spec` не зависит от файловой системы, архивов, GUI или OS API.
- `luxury-engine` содержит use case и порты; `luxury-platform` реализует реальные мутации ОС.
- Business logic, package policy, rollback и receipt остаются в Rust. Tauri 2 + React/TypeScript — только presentation shell и composition boundary.
- Tauri Rust shell общается с backend только через versioned typed JSONL `luxury stdio` по stdin/stdout. Валидируй Tauri invoke/event и JSONL с обеих сторон; human logs запрещены в protocol stdout.
- Setup не является `.luxpkg`-браузером: Tauri Rust shell привязывает один payload при bootstrap, renderer не получает package path/fingerprint и не показывает chooser/drag-and-drop.
- Renderer использует только exact Tauri ACL. Не выдавай ему shell/fs/dialog/opener/process permissions; native dialogs и backend lifecycle принадлежат Rust shell.
- Tauri остаётся exact-pinned и собирается с `default-features = false`; не включай runtime `dynamic-acl`. Linux release закрыт, пока final lock содержит `glib 0.18.5` / `RUSTSEC-2024-0429`.
- `apps/luxury-installer/src-tauri` — отдельный Cargo workspace со своим `Cargo.lock`; не добавляй его в корневой workspace и не втягивай Tauri в `cargo quick`.
- Отдельный Tauri workspace обязан сохранять компактные `dev/test` profiles с `debug = "line-tables-only"`; корневые Cargo profiles он не наследует.
- Desktop имеет два явных build flavor: default `studio` без payload и `setup` с одним bound payload. Setup assembly всегда использует `--no-default-features --features setup`; не определяй режим release через наличие/отсутствие файла.
- Release Setup обязан компилироваться с exact lower-hex review fingerprint выбранного payload; только `xtask` задаёт `LUXURY_BOUND_PACKAGE_FINGERPRINT`, а Studio build удаляет эту env. Runtime повторно сравнивает embedded binding с inspected package до UAC.
- Перед любым authenticated `runas` Windows shell удерживает exact single-link non-reparse helper без write/delete sharing и сравнивает его embedded Authenticode leaf с process-image-bound signer реально запущенного Tauri launcher. Guard живёт через `ShellExecuteExW`; catalog signature, имя publisher, hash без chain, caller pin или unsigned fallback не являются authority.
- Package path не пересылается privileged helper: unelevated parent удерживает regular single-link non-reparse handle, helper после PID/signer checks дублирует его из authenticated parent process. Request связывает exact operation ID/action/package ID/fingerprint; handle value — routing data, не secret/trust anchor.
- System roots не приходят из renderer/JSONL/argv/env: Windows использует Known Folders, Linux/macOS — фиксированные absolute roots. Private-state policy всегда получает explicit `InstallScope`: Windows system = elevated + SYSTEM/Administrators-only ACL/owner, Unix system = root-owned `0700/0600`. Windows install/uninstall/launch идут через action-separated one-shot helper; launch использует checked unelevated parent token. Linux использует только fixed root-owned helper + exact polkit policy, per-frame `SO_PASSCRED`, один `SCM_RIGHTS` package FD и credential drop перед launch; extracted writable tar не получает system authority. macOS использует только signed `SMAppService` LaunchDaemon, audit-token designated requirements, socket-activated seqpacket и signed-resource package FD; unsigned/dev bundle обязан fail-closed.
- Linux/macOS Studio и Setup публикуются только через Rust-generated deterministic `.tar.gz`, сохраняющий executable intent; CI не загружает raw Unix directory, потому что transport сбрасывает mode bits.
- Не добавляй `common`, `utils`, фабрики с одной реализацией или feature-флаги «на будущее».
- Любой путь из пакета недоверенный. Запрещены absolute/parent/UNC/device/ADS, ссылки и platform-dependent aliases.
- Любая мутация установки обязана иметь rollback и ownership receipt вне удаляемого дерева.
- Быстрый Rust-цикл: `cargo quick`. GUI проверяется отдельно: `cargo gui-check`; routine CI отдельно запускает узкий Windows gate `luxury-windows-trust + luxury-platform`. Перед первым GUI gate выполни `pnpm --dir apps/luxury-installer install --frozen-lockfile`. Полная нативная матрица — только перед релизом.
- `cargo linux-packages -- <package.luxpkg>` запускается только нативно на Linux и вне routine gates: pinned Tauri bundler создаёт `.deb`/RPM, Rust независимо проверяет exact layout/ownership/modes/hashes/scripts/dependencies и публикует только unsigned development provenance.
- macOS release flow: exact signed/stapled `.app` -> `cargo macos-dmg` -> external Developer ID sign/notary/staple -> `cargo verify-macos-dmg`; команды не принимают credentials и не считают unsigned DMG релизом.
- Не запускай подряд одинаковые `check/clippy/test` без новой информации; один gate — одна цель.
- Не коммить ключи подписи, сертификаты, токены, собранные payload, Tauri `gen/schemas`/`permissions/autogenerated` и временные QA-файлы.
- Обновляй корневой `MEMORY.md`, когда меняются границы архитектуры, формат пакета или build contract.
