## 2026-08-03 — explicit completion, bounded details, and safe finish links

Renderer receives labels/URLs for display validation but invokes only `open_finish_link(index)`; Rust retains the authenticated list and refuses opening before a successful current-session install. Arbitrary schemes, commands, auto-run, arguments, and environment changes remain forbidden.

## 2026-08-01 — independent meta-review: pre-UAC trust and protocol alignment

- Windows authenticated elevation now closes the pre-launch pathname window, not only the post-launch handshake: Tauri opens the exact helper as a single-link non-reparse file without write/delete sharing, verifies its embedded leaf certificate against the `ProcessImageFileMapping`-bound signer of the running launcher, retains the guard through `ShellExecuteExW`, then repeats PID/token/running-image checks in the elevated helper. The unsigned `--verify-elevated-transport` QA path keeps its signer-independent behavior but receives the same pathname guard.
- JSONL v2 error messages now replace control characters and cap exact UTF-8 bytes to the same 1024-byte client contract; all-control errors fall back to `operation failed`. Tauri progress decoding rejects counters above one JS safe integer before renderer delivery, and the one shared Rust constant also governs system frames and Studio/Setup payload totals.
- Repeated native close no longer bypasses an in-progress Setup rollback: `close_started` serializes shutdown, `close_ready` permits only the final Rust-initiated window close after terminal cleanup/backend shutdown, and every intermediate CloseRequested/Alt+F4 remains prevented. User-operation cancel waits at most the remaining shared shutdown budget instead of starting a fresh 15-second allowance after the deadline.
- Compiler publication no longer implements its own deterministic `exists -> backup -> rename` namespace. The already-present `tempfile` crate is now a direct compiler dependency: one same-directory `NamedTempFile` is flushed/synced and atomically persisted over a validated regular output, while link/reparse/non-file targets remain rejected. This removes the backup-name race and artificial 100-name ceiling without adding a new runtime package.
- Meta-review reverted the previous renderer phase-order regression: the engine intentionally authenticates package bytes before recovery, so UI ordering is `validating -> verifying -> recovering -> planning`. One combined “Проверка состояния” item remains active through verify/recover without inventing another authority or screen.
- Routine CI now has a focused Windows `luxury-windows-trust + luxury-platform` job. Node runtime/types stay aligned at `22.12.0`; Lucide uses supported named exports; Tauri `gen/schemas` and `permissions/autogenerated` remain generated/ignored instead of open-source payload.
- CI jobs are explicitly bounded: format 10 min, quick and Windows boundary 30 min, GUI/native hosts 60 min, evidence merge 20 min. The existing separated gates remain authoritative; no serial mega-job or new dependency was added.
- Final current-tree evidence after the repeated meta-review: root CLI 50/50; `luxury-windows-trust` 3/3; `luxury-platform` 114/114; `luxury-compiler` 14/14; standalone Tauri 42/42; renderer contracts 11/11; focused JSONL regression 1/1. `cargo gui-check` passed contracts, strict TypeScript, Vite, and both Studio/Setup Rust graphs; production renderer output is 94.87 KiB JS gzip and 4.44 KiB CSS gzip. ## 2026-07-30 — Windows Authenticode identity, package-specific Setup и fixed system roots

- Новый focused crate `luxury-windows-trust` использует native `WinVerifyTrust` с UI disabled, whole-chain revocation policy и MD2/MD4 disabled, извлекает verified leaf certificate из provider state и возвращает только SHA-256 его DER. `cargo verify-windows-signers -- <launcher.exe> <helper.exe>` требует две embedded signatures и exact certificate equality; unsigned/current Luxury binaries дают `TRUST_E_NOSIGNATURE`, catalog-only Windows binaries также не считаются portable-helper authority, разные valid signers отклоняются. Positive gate прошёл на embedded-signed Chrome.
- Hidden `privilege-probe-authenticated` требует elevated token, получает actual Tauri server PID и image path через named pipe/kernel APIs, сравнивает WinTrust identities helper/server и повторно проверяет server PID перед challenge. Tauri modifier `--verify-authenticated-transport` является headless-only; на текущих unsigned debug bytes он корректно печатает redacted failure и теперь возвращает exit 1. Для этого общий Tauri exit path переведён на `run_return` + explicit requested-code override; success `--verify-elevated-transport` остаётся exit 0.
- Release Setup shell теперь package-specific: `xtask` очищает `LUXURY_BOUND_PACKAGE_FINGERPRINT` для Studio и задаёт exact inspected lower-hex review fingerprint только для Setup build; release Setup повторно сравнивает embedded binding с payload до UAC. Fingerprint связывает manifest/signer/object hashes, но helper ещё обязан reopen/match package при реальной operation.
- `default_system_roots()` не принимает caller/env roots: Windows использует `FOLDERID_ProgramFiles`/`FOLDERID_ProgramData`, Linux — `/opt/luxury-installer/apps` + `/var/lib/luxury-installer`, macOS — `/Applications` + `/Library/Application Support/Luxury Installer/State`. Helper из duplicated handle требует unsigned format v1, exact fingerprint/ID, host target и `scope=system`, затем сам получает fixed roots. ## 2026-07-30 — trusted entrypoint и явный receipt-owned launch

- Package trust `format_version` v1/v2/v3 и manifest capability `schema_version` теперь независимы. Отсутствующий schema остаётся legacy v1 и сериализуется без нового поля. - Rust `launch` принимает только package ID. Engine проверяет pending recovery → current receipt → receipt validity/package ID → exact owned `FileEntry`; platform затем под package→destination locks повторно проверяет recovery/receipt/file, hash/size/link count и Unix mode. Оба recovery check сохраняют wire `recovery_required`: under-lock race использует отдельный `PortErrorKind::Recovery`, а не общий повреждённый state. Перед `Command` install base переводится в absolute OS path, поэтому relative human-CLI roots не удваиваются вместе с cwd. Spawn — direct `Command`, absolute install root как cwd, без shell/args, stdin/stdout/stderr = null. Windows удерживает complementary write/delete guards через spawn. Unix до spawn создаёт detached reaper thread и передаёт ему direct child, поэтому long-lived stdio не копит zombies; цена — один thread до завершения каждого запущенного child. Verified fd остаётся жив через spawn, но pathname повторно разрешается `Command`, поэтому Unix ABA, Windows parent/reparse retarget и pre-existing writable mappings остаются documented same-user ceilings.
- Human CLI: `luxury launch <package-id> <install-base> <state-root>`. JSONL v2 additive `launch` использует тот же strict packageId/installBase/stateRoot shape и возвращает только `launched + packageId`; renderer получает только `hasEntrypoint` и отправляет zero-arg invoke. Rust Tauri shell подставляет bound ID/roots. Launch занимает общий exclusive slot, public cancel его отклоняет, потому что успешный spawn нельзя rollback'нуть. Shell не ставит неоднозначный post-spawn timeout: timeout после spawn дал бы ложную ошибку и двойной запуск при retry; app shutdown всё равно закрывает stdio и drain/reap child. Setup показывает кнопку только после успешной установки и никогда не auto-runs.
- `cargo runner-smoke` имеет отдельный schema-v2 package с временно скомпилированным Rust helper: helper отклоняет args, делает `sync temp marker → close → atomic rename`, затем принимает exact loopback token, сразу отправляет exact ACK и завершает write half best-effort перед обычным return. Helper не ждёт дополнительный EOF после уже exact-length token: Windows может представить корректный peer half-close как reset и оборвать ACK. Bounded EOF либо Windows `ConnectionReset` после exact ACK + native PID wait в том же deadline доказывают завершение до обычного receipt-owned uninstall и на Unix проверяют работу child reaper. Helper компилируется вне payload; внутрь публикуется только executable, без MSVC PDB sidecar. Launch обязателен для gate, но намеренно не добавлен отдельным field в evidence schema v2, как recovery/cancellation.

## 2026-07-30 — bounded progress между Rust stdio и Tauri renderer boundary

## 2026-07-30 — `RenameDurability` для production no-clobber mutations

- Все 12 production-вызовов no-clobber rename теперь обязаны обработать `#[must_use]` token, который отделяет успешную pathname mutation от результата persistence barrier. На Windows token zero-sized: `MoveFileExW` уже вызывается с документированным `MOVEFILE_WRITE_THROUGH`. Это не привязывает parent path/reparse chain и не доказывает общую Windows directory durability.
- На Linux/macOS rename открывает source и destination parents descriptor-relative с `NOFOLLOW`. Один и тот же lexical parent открывается один раз, после чего `F_DUPFD_CLOEXEC` создаёт второй descriptor того же inode. Token sync'ит destination, затем source: Linux использует `fsync`, macOS — `F_FULLFSYNC`; `EINTR` повторяется, а `EINVAL`/`EOPNOTSUPP`/`ENOTTY` становятся typed `unsupported` без fallback. Descriptor-relative Unix unlink использует тот же sync helper.
- Разрешённая гарантия узкая: после успешного открытия обоих Unix parents замена parent path не может перенаправить уже открытые parent descriptors или их flush, и оба flush syscall вернули success. Source leaf остаётся name-bound/ABA. Это не power-loss и не cross-platform-race-safe claim.
- Все production `.exists()`-ветви внутри local transaction/recovery заменены на fail-closed `path_present`. Regression с dangling live receipt сохраняет installed bytes и WAL вместо ошибочного перехода в missing-state cleanup.
- Replacement, uninstall, obsolete quarantine и inverse restore теперь до rename hash+sync'ят source на одном no-follow movable handle. На Windows этот R/W handle разрешает `READ|DELETE`, но не `WRITE`; после move отдельный read handle разрешает `READ|WRITE`, но не `DELETE`, привязывает новое имя к тому же file ID, а исходный handle повторно hash+sync'ит size/mode/link count. Оба handle живут до `RenameDurability::sync`; stationary survivor comparisons сохраняют более строгий delete-denying guard. Unsyncable readonly/restrictive-reader source на новом quarantine ingress отказывает до `RestoreFile` intent и rename; при recovery — до inverse rename с сохранённым WAL. Upgrade rollback последовательно sync-проверяет все eventual backups/survivors до первого удаления нового live-файла.
- Не закрыты: Windows pathname/reparse/parent binding и generic create/delete sync; Unix pre-open/source-leaf ABA; mapped-writer и hostile same-user namespace races; после non-`EINTR` token error exact descriptors теряются, а recovery не переигрывает обе barriers до cleanup; поздний reader после sequential prevalidation ещё может оставить идемпотентный partial rollback с сохранённым WAL; Windows readonly/restrictive-reader source не получает copy/delete fallback; нет native macOS/APFS и VM power-cut proof.

Upgrade commit point — `receipt.pending -> receipt` после rollbackable `receipt -> receipt.previous`; pre-commit recovery возвращает старые bytes+receipt, post-commit recovery оставляет новые и чистит backups. Torn journal tail обрезается только после exact-prefix recheck перед rollback marker. Reader сохраняет parsing bound legacy journal v2/v3 только как `user`; legacy uninstall без receipt binding не даёт authority для автоматического изменения receipt/payload.
- Platform резервирует case/NFC-normalized install-directory namespaces `.luxury-locks` и `.luxury-tx-*`; package не может смешать payload с locks/staging либо заблокировать чужой package ID.
- Install root обязан быть disjoint с `state_root/receipts`, `state_root/transactions` и `state_root/locks` в обе стороны; `install_base == state_root` допустим только для другого sibling directory без пересечения internal state.
- Committed uninstall перед удалением tombstone атомарно публикует `journal.done` через native no-clobber rename (`MOVEFILE_WRITE_THROUGH` на Windows, parent sync на Unix). Recovery принимает marker только как bound uninstall journal с последним `Committing`, без live receipt и destination transaction directory; `journal + journal.done`, чужие entries и recreated live receipt сохраняются с ошибкой. Marker не используется для install/rollback. Общая Windows directory-fsync гарантия и native power-loss matrix остаются release-блокерами.
- Existing receipts, journals, hashed files, hard-link pairs и persistent locks теперь открываются через единый handle-first no-follow primitive: `O_NOFOLLOW | O_NONBLOCK` на Linux/macOS и `FILE_FLAG_OPEN_REPARSE_POINT` на Windows. Тип, размер и link count проверяются по открытому handle; hash повторно проверяет link count после чтения. Это закрывает final-component check/open race без новой dependency. Parent-component races, pathname-bound rename/remove и concurrent writer integrity остаются отдельными release-блокерами.
- Не повторять псевдо-pinning Windows parent chain через directory handles без `FILE_SHARE_DELETE`: нативный тест Windows NT 10.0.26200 показал, что `fs::rename` и `fs::remove_dir` родителей всё равно проходят при живых handles. Документированный `SetFileInformationByHandle(FILE_RENAME_INFO)` работает с absolute target, но relative leaf + non-null `RootDirectory` на этом host возвращает `ERROR_INVALID_PARAMETER (87)` для `FileRenameInfo` и `FileRenameInfoEx`. Полное закрытие требует отдельного проверенного handle-relative/oplock design, а не claim поверх `MoveFileExW`.
- Install engine повторно аутентифицирует открытый bundle до `recover_pending`; непроверенный или подменённый пакет не может запустить recovery-мутацию.
- Platform receipt envelope v2, ownership receipt v4 и journal v4 привязаны к SHA-256 точного canonical OS path и filesystem/directory identity исходного `install_base`; readers принимают bound legacy journal v2/v3 как `user` и ownership receipt v1-v3. Replay через другой base или scope отклоняется до destination mutation. Старые unbound preview-state отклоняются и сохраняются без автоматической миграции. Descriptor-relative защита родителей, handle-bound mutations и native durability остаются release-блокерами.
- `.luxpkg` v1/v2/v3 хранит payload content-addressed как `objects/sha256/<digest>`. Manifest связывает object с проверенным логическим destination path.
- Bundle open для `inspect` и `install` cancellable: decompressed reads ограничены chunk до `64 KiB`; tar footer читается bounded буфером `513 bytes` (ровно `512` zero bytes допустимы), а valid path всё равно доходит до gzip checksum и проверяет отсутствие trailing compressed data.
- V1 unsigned: SHA-256 подтверждает целостность, но не publisher; install требует явное `--allow-unsigned`/`allowUnsigned` согласие.
- V2/v3 signed: `META/signature.ed25519` содержит key ID + Ed25519 signature domain-separated transcript точных manifest bytes. Build принимает bounded PKCS#8 PEM private key только через stdin (`--signing-key-stdin`); inspect/install принимают внешний SPKI PEM trusted public key. Отсутствующий/чужой/невалидный key/signature/PoP отклоняется без downgrade в unsigned.
- Ownership receipt v4 атомарно хранит verified `authorized_publisher`, `payload_signer` и optional entrypoint; inner v1-v3 читаются без фоновой миграции, но legacy entrypoint запрещён. Identity возвращает `LocalInstallAdapter::verify_package` из authenticated `Bundle`, а не CLI/renderer. Legacy→any и unsigned→trusted требуют отдельный caller approval; trusted rotation разрешает только authenticated v3 policy выше; trusted→unsigned fail-closed.
- JSONL v2 запускается как `luxury stdio [--trusted-publisher-key <absolute SPKI PEM>]`; private key и claimed identity никогда не передаются через JSONL. `allowPublisherMigration` additive/default false и передаёт только authority для legacy/unsigned adoption. Rust Tauri shell получает migration requirement из Rust prepare, binds его к internal roots + bound fingerprint и только затем принимает renderer consent; backend error остаётся защитным recheck. Rotation metadata приходит только из verified inspect и никогда не является install input.
- Migration offer не содержит exact prior-receipt hash/from-identity challenge; он bound к roots+package fingerprint, а Rust разрешает им только legacy→current и unsigned→trusted, поэтому trusted-key bypass отсутствует. Authenticated rotation не использует этот offer.
- Один артефакт не может быть нативным сразу для трёх ОС. `cargo assemble -- <package.luxpkg>` собирает только unsigned-v1 development runner текущего host: fresh staging, dist Rust backend, checked frontend, standalone locked Tauri release shell, fixed `backend` + `payload` resources, отсутствие trust resource, SHA-256/JSONL verification, windowless запуск packaged Tauri `--verify-runner` и no-clobber publish в ignored `dist/`. Signed v2/v3 runner fail-closed: public key рядом с payload внутри неподписанного изменяемого bundle не является trust anchor. Его assembly разрешается только вместе с проверяемой native container signature или внешним out-of-band trust root. Cross-compilation, native installer/container signing, Authenticode/codesign/notarization и полная native install/recovery/signature matrix ещё не реализованы.
- Trust boundary: manifest/archive/path/state считаются недоверенными; arbitrary post-install shell scripts запрещены. Единственный launch target — exact receipt-owned entrypoint без args, package-controlled env и auto-run. Остальные typed actions допустимы только вместе с validation/rollback/timeout/cancellation/privilege contract.
- `0.1.x` — development preview, не production-ready. Parent descriptor-relative races, handle-bound mutation/writer integrity, native durability и независимое release security sign-off ещё не закрыты.

## Build contract

- Toolchains: pinned Rust `1.96.0`, Node.js `>=22.12`, pnpm `10.26.2`.
- Однократный bootstrap GUI: `pnpm --dir apps/luxury-installer install --frozen-lockfile`.
- `cargo quick` — повседневный Rust gate для product crates, CLI и `xtask`; standalone Tauri workspace в него не входит.
- `cargo gui-check` — renderer contracts + strict TypeScript + Vite production build + locked standalone Tauri check через `xtask`; зависимости заранее установлены.
- `cargo tauri-test` и `cargo tauri-clippy` — отдельные gates standalone Tauri Rust shell.
- `cargo full-test` — полный Cargo gate только перед release candidate.
- `cargo dist` собирает host Rust backend и checked Tauri frontend, но не готовый native installer, не native-подпись и не cross-platform smoke proof.
- `cargo assemble -- <package.luxpkg>` отдельно собирает и проверяет только unsigned-v1 development runner текущего host, включая отсутствие trust resource и packaged Tauri `--verify-runner` без окна, без full release matrix и без перезаписи существующего артефакта. Signed v2/v3 inspect/install остаются доступны human CLI/stdio/development Setup только с внешним SPKI trust anchor; signed build остаётся CLI stdin-only, а packaged Tauri runner не читает co-packaged key.
- `cargo studio-assemble` отдельно собирает no-clobber payload-free Studio текущего host, проверяет exact launcher/backend layout и windowless `--verify-studio`; это unsigned development artifact, не platform-signed release.
- Manual Windows/Linux/macOS x86_64 CI matrix перед Setup runner-smoke также запускает `cargo studio-assemble` и загружает проверенный payload-free Studio artifact; наличие workflow не заменяет скачанное evidence конкретного run.
- Studio/Setup assembly проверяет exact host layout до и после runtime probe, связывает copied launcher/backend/payload с SHA-256 исходных build/package bytes и запрещает любые extra top-level/resource entries. Linux additionally stages exact helper/polkit policy; macOS stages exact helper/LaunchDaemon plist and a 13.0 floor. После успешного install Tauri shell кэширует и отправляет renderer maintenance review (`repair`, installed version, uninstall available); cancellation/rollback refresh получает новое Rust preparation перед retry.
- `LUXURY_APPLE_TEAM_ID` — compile-time canonical 10-character trust input for both macOS app/helper builds, never renderer/JSONL input. `cargo verify-macos-release -- <signed.app>` runs only on macOS and requires strict designated requirements, nested codesign, Gatekeeper acceptance and a stapled notarization ticket; it does not sign or own credentials.
- `cargo runner-smoke` один раз собирает dist backend, создаёт временные host-target lifecycle/recovery/launch packages, выполняет packaged recovery/cancellation/launch/install/uninstall + Tauri `--verify-runner` вне `dist/`, считает cleanup частью gate и публикует только local evidence schema-v2 JSON в ignored `target/runner-evidence`.
- Launch QA helper после exact loopback token отправляет ACK, делает TCP `shutdown(Write)` и завершается обычным return; немедленный `process::exit(0)` запрещён, потому что на Windows он мог обрезать ACK/RST и флакать доказательство PID-exit.
- Текущий Windows x86_64 runner-smoke после Tauri migration прошёл все stages и опубликовал schema-v2 evidence; это не заменяет ещё отсутствующий downloaded Linux/Windows/macOS evidence set.
- Routine pull-request/main CI остаётся separate `format + cargo quick --locked + cargo gui-check + Windows luxury-windows-trust/luxury-platform`; manual `workflow_dispatch` запускает `cargo full-test --locked`, standalone Tauri tests и lifecycle runner smoke на Ubuntu, Windows и macOS (Linux под Xvfb), затем загружает per-host evidence. Успешный job gates launch/cancellation/recovery, но strict schema-v2 JSON сам по себе их отдельно не кодирует и не является native signature proof.
- Не запускать подряд одинаковые broad gates без новой информации.

## Decision rule

Новая абстракция допустима только если есть вторая реальная реализация/платформа или она отделяет privilege, process либо filesystem boundary. Иначе остаётся обычной функцией в текущем slice.
